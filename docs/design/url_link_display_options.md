# URLリンク表示機能 実現方式案

## 背景
ユーザー要望「URLを張り付けたらURLリンク表示したい」を実現するため、以下の3つの案を策定しました。

## 提案1: レンダラーでの自動リンク検出
`SvgRenderer`でノードのテキスト(`topic`)を描画する際に、正規表現でURLを検出し、自動的に`<a>`タグに変換して表示します。

*   **メリット**:
    *   実装コストが最も低い。
    *   データ構造(`Node`エンティティ)の変更が不要。既存データも即座に対応可能。
*   **デメリット**:
    *   URLがそのまま表示されるため、長いURLだと見栄えが悪い（例: `https://example.com/very/long/path...`）。
    *   リンクテキスト（表示名）を指定できない。

## 提案2: Markdownリンク記法のサポート
ノードのテキスト内でMarkdownのリンク記法 `[表示テキスト](URL)` をサポートします。レンダラーでこれをパースしてリンクとして表示します。
例: `[Kakidash](https://github.com/hiroooo000/kakidash)`

*   **メリット**:
    *   リンクの表示テキストを自由に設定でき、見栄えが良い。
    *   データ構造の変更が不要。
    *   エンジニアにとって馴染み深い記法。
    *   将来的なMarkdown記法（太字、斜体など）の拡張基盤になる。
*   **デメリット**:
    *   簡易的なMarkdownパーサーの実装が必要（ライブラリ依存を避けるため）。
    *   ユーザーが記法を覚える必要がある（ただし自動変換も実装可能）。

## 提案3: ノードプロパティへのURL項目の追加
`Node`エンティティに`url`プロパティを追加し、テキスト(`topic`)とは別にURLを管理します。

*   **メリット**:
    *   データ構造として最もクリーン（テキストとメタデータの分離）。
    *   UI上でリンクの存在を明確に表現しやすい（例：テキスト横にアイコンを表示）。
*   **デメリット**:
    *   実装コストが高い（Domain, Application, Presentation全層の修正が必要）。
    *   UIにURL編集用の入力欄を追加する必要がある。

## 比較表

| 項目 | 提案1 (自動リンク) | 提案2 (Markdown) | 提案3 (プロパティ追加) |
| :--- | :--- | :--- | :--- |
| **実装コスト** | 低 | 中 | 高 |
| **データ構造変更** | なし | なし | あり (`url`追加) |
| **表現力** | 低 (URLそのまま) | 高 (テキスト変更可) | 高 (専用UI可) |
| **アーキテクチャ影響** | Presentationのみ | Presentationのみ | 全レイヤー |
| **拡張性** | 低 | 高 (太字等も対応可) | 中 |

## 推奨案
**提案2 (Markdownリンク記法)** を推奨します。
アーキテクチャへの影響を最小限に抑えつつ、ユーザーがリンクテキストを制御できる柔軟性があるためです。また、ライブラリを追加せずとも正規表現を用いたシンプルな置換で実装可能です。
